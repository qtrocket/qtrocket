## P1 — Make the physics honest: drag + the atmosphere (keystone, days)

- [✅] **Implement aerodynamic drag** in `RocketModel::getForces`: `F_drag = -½·ρ(altitude)·|v|·v·Cd·A`, with `ρ` from the active atmospheric model. Added a `referenceArea` member (Cd already existed), a `VacuumAtmosphere` model, and `setatmosphere`/`setarea` CLI commands. Altitude is clamped to ≥0 at the density query (USStandardAtmosphere's Bin lookup throws below 0). Terminal velocity verified manually via `qtrocket-cli` and now covered by an automated test (see below).
- [✅] **⚠ Fix RK4 force evaluation while adding drag** — `getForces` now takes `(t, position, velocity)` and the Propagator's ODE lambda passes each RK4 trial state ([Propagator.cpp](sim/Propagator.cpp)), so velocity-dependent drag integrates at full RK4 accuracy instead of degrading to Euler.
- [✅] **Add automated CTest coverage for the new physics** — [tests/PhysicsIntegrationTests.cpp](tests/PhysicsIntegrationTests.cpp) (suite `qtrocket_integration_tests`) drives the real `RocketModel`/`Propagator`/`Environment` end-to-end: timestep invariants under `Vacuum` (step count ∝ 1/dt, flight time ~constant, sample interval == dt), drag-reduces-apogee vs vacuum, terminal-velocity force balance under `Constant Atmosphere`, and a US-Standard no-crash regression guard. No mock Propagatable — atmosphere selection makes the runs drag-free or not as needed.

### P0.5 — Close GUI↔CLI parity gaps & remove two traps (do these first; hours)

*New, from [ANALYSIS_RESULTS_1.md](docs/ANALYSIS_RESULTS_1.md) §9 (evidence in §3–§4). The P0 work made launch angle and timestep functional, but the GUI didn't keep pace — a few inputs are now dead, disabled, or unsafe, which re-introduces the "stop lying to the user" problem on the GUI side. Tags **[H]/[M]/[L]** cross-reference that document's severity.*

- [✅] **[H2] Validate the timestep in the setter so neither front-end can hang.** `Propagator::setTimeStep` now rejects any `dt` that isn't `> 0` (the `!(ts > 0.0)` test also catches NaN), logs a `warn`, and keeps the previous valid step instead of storing the bad one — so a `setTimeStep(0)` degrades to "no change" rather than the old infinite `runUntilTerminate` loop. The guard lives at the one shared chokepoint, so the GUI (Sim Options), CLI, and tests are all covered; `QtRocket::setTimeStep` just forwards into it. The Sim Options field also got a real default `text` of `0.01` (not just a placeholder) plus a `QDoubleValidator(bottom>0)` for immediate feedback. Regression test: `PhysicsIntegrationTest.NonPositiveTimestepIsRejectedAndDoesNotHang` (dt=0 and dt<0 leave the flight identical to the last valid step). 19/19 CTest pass.
- [✅] **[H1] Enable the GUI launch-angle field + swap angle convention to "from vertical".** The `initialAngle` field is unlocked (removed `enabled=false`/`readOnly=true`) with a `QDoubleValidator(0–90)` and a tooltip ([MainWindow.ui](gui/MainWindow.ui#L94-L102), [MainWindow.cpp](gui/MainWindow.cpp)). The launch-angle convention was changed from **degrees-from-horizontal** to **degrees-from-vertical** (0 = straight up, 90 = horizontal) across both front-ends: the velocity mapping is now `vx = v·sin(θ)`, `vz = v·cos(θ)` in [MainWindow.cpp](gui/MainWindow.cpp) and [Repl.cpp](cli/Repl.cpp), the CLI default/help/status and `initialAngleDeg` default flipped to `0.0` ([Repl.h:57](cli/Repl.h#L57)). The engine is untouched (it takes velocity components, not angles). The `PhysicsIntegrationTests` helper adopts the same convention and a new `LaunchAngleFromVerticalProducesDownrange` test locks it (0° → no downrange/full apogee, 45° → downrange>0/lower apogee). Verified live: `qtrocket-cli` at 45° (Vacuum, 30 m/s) gives **547 m downrange** vs 0 m at 0°. 20/20 CTest pass.
- [✅] **[M1] Add a reference-area input** next to `Cd`, wired to `RocketModel::setReferenceArea` ([RocketModel.h:112-117](model/RocketModel.h#L112-L117)). Added a "Reference Area" field (default `0.001134 m²`, `QDoubleValidator(bottom=0)` matching the CLI's `setarea`) to the Cannonball input form — note the inputs now live in [gui/CannonballTab.ui](gui/CannonballTab.ui) after the tab extraction, not MainWindow — applied to the rocket at Calculate Trajectory alongside mass/Cd.
